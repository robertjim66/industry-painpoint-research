>

## 为什么要有「最小可行报告」样例

大多数工具的文档只展示成功样例。但判断一个调研系统好不好，**要看它没东西可说的时候怎么办**。

`sample-output-minimal.md` 展示的是：当行业公开信息严重不足时，系统不会硬凑一份看起来很完整的报告，而是明确交出「能确认的 + 找不到的」两张清单。这是这套系统最不一样的地方，也是最容易被人忽略的地方。

## 运行示例行业

样例统一使用 **第三方医学检验** 行业作为示范对象。选它的原因：

- 公开信息密度适中（不是最热也不是最冷）
- 价值链清晰（上游试剂设备 → 中游检验实验室 → 下游医院/体检/个人）
- 八类痛点里能命中 5 类以上，适合展示痛点矩阵

你换成任何行业都一样跑。

## 想贡献真实样例？

非常欢迎。真实报告是最好的测试用例。提交前请：

1. **脱敏** — 去掉客户名、内部数据、不便公开的信息
2. **保留来源链接** — 这正是样例的价值所在，去掉了就只剩结构
3. **保留降级痕迹** — 如果某个环节标注了「数据不足」，别把它删掉补成完整版，那恰恰是最有价值的部分
4. 放进 `examples/real/<行业名>.md`，并在本文件列表里追加一行

详见主 [README](../README.md) 的「贡献」一节。
